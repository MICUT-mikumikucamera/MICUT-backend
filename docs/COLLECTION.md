# MiCut 컬렉션 API 변경 사항 (명세 v0.3)

2026-11-13 기준 · 컬렉션과 관련해 바뀐 내용만 모았어요. 전체 명세는 `docs/API.md`에 있어요.

## 요약

| 구분 | API | 내용 |
| --- | --- | --- |
| 신규 | `GET /api/v1/collection` | 카드 12장과 내가 얻은 사진 목록 조회 |
| 변경 | `POST /api/v1/jobs` (사진 접수) | 선택 헤더 `X-Device-Id` 추가 |
| 변경 | `GET /api/v1/jobs/{job_id}` (상태 조회) | `done` 결과의 `card_ids`가 채워지고, `new_card_ids` 추가 |
| 변경 없음 | 재시도, discard, 결과 이미지, `/health` | 재시도 끝에 `done`이 되면 그때 카드를 얻어요 |

헤더를 보내지 않는 지금 앱도 그대로 동작해요. 그 경우 카드는 정해지지만 컬렉션에 기록되지 않아요.

## 1. 사용자 구분: `X-Device-Id` 헤더

지금은 로그인이 없어서 컬렉션을 **기기별로** 쌓아요. 앱을 처음 실행할 때 UUID를 하나 만들어 기기에 저장하고, 사진 접수와 컬렉션 조회에 `X-Device-Id` 헤더로 보내 주세요.

- 형식: 1~64자, 영문·숫자·`-`·`_` (예: `3f2b8c1e-5d4a-4e7b-9c0d-1a2b3c4d5e6f`)
- 형식이 틀리면 `422 INVALID_REQUEST`
- 앱을 지우면 새 ID가 만들어지므로 컬렉션도 처음부터 시작해요.

> **로그인 기능이 추가될 예정이에요.** 그때 사용자 구분 방식(헤더, 기존 기기 기록 처리)이 바뀔 수 있고, 로그인 명세에서 함께 정할게요. 기기 ID는 그 전까지 쓰는 임시 방식이에요.

## 2. 사진 접수 변경 — `POST /api/v1/jobs`

| 헤더 | 필수 | 설명 |
| --- | --- | --- |
| `X-Device-Id` | X | 보내면 이 사진으로 얻은 카드가 그 기기의 컬렉션에 기록돼요 |

폼 필드(`photo`, `w`, `h`, `rotation`, `fx`, `crop`)와 응답 모양은 그대로예요.

## 3. 상태 조회 변경 — `GET /api/v1/jobs/{job_id}`

`done`일 때 `result`

```json
"result": {
  "image_url": "/results/j_20261114_a1b2c3d4e5f6-1.png",
  "tags": [],
  "card_ids": ["v_sign"],
  "new_card_ids": ["v_sign"]
}
```

| 필드 | 설명 |
| --- | --- |
| `card_ids` | 이 사진으로 얻은 카드 id. 지금은 항상 1장 (전에는 항상 빈 배열) |
| `new_card_ids` | **신규.** `card_ids` 중 이 기기가 처음 얻은 카드. 비어 있지 않으면 "신규 컬렉션 획득!" 팝업을 띄워 주세요. 접수 때 `X-Device-Id`를 안 보냈으면 항상 빈 배열 |

- 2026-11-13 이전에 끝난 작업은 `card_ids`, `new_card_ids` 모두 빈 배열이에요.
- 팝업에 쓸 카드 이름과 번호는 아래 카드 목록(또는 컬렉션 조회 응답)에서 `id`로 찾아 주세요.

## 4. 신규 — 컬렉션 조회 `GET /api/v1/collection`

헤더 `X-Device-Id` (필수)

카드 12장 전체와, 이 기기가 각 카드를 얻은 사진 목록을 한 번에 줘요. 컬렉션 화면(진행도·잠긴 카드)과 카드 상세 화면(사진 여러 장·날짜)을 이 응답 하나로 그릴 수 있어요.

응답 `200`

```json
{
  "acquired_count": 1,
  "total": 12,
  "cards": [
    { "id": "gyaru_peace", "no": 1, "name": "갸루 피스", "photos": [] },
    {
      "id": "v_sign", "no": 2, "name": "브이",
      "photos": [
        { "job_id": "j_20261114_a1b2c3d4e5f6", "acquired_at": "2026-11-14T15:00:00+09:00" }
      ]
    }
  ]
}
```

위 예시는 줄인 것이고, 실제로는 12장이 다 와요.

| 필드 | 설명 |
| --- | --- |
| `acquired_count` | 얻은 카드 수 (진행도의 분자) |
| `total` | 전체 카드 수 (진행도의 분모, 12) |
| `cards` | `no` 순서 |
| `cards[].no` | 화면의 `#001` 번호 |
| `cards[].name` | 못 얻은 카드에도 와요. 잠긴 카드는 앱에서 `???`로 가려 주세요 |
| `cards[].photos` | 이 카드를 얻은 사진들, 얻은 순서(오래된 것 먼저). 비어 있으면 못 얻은 카드 |
| `photos[].job_id` | 앱이 기기에 저장한 결과 이미지를 찾을 때 써요 |
| `photos[].acquired_at` | 카드 상세의 날짜 |

- 서버 응답에는 이미지 주소를 넣지 않아요. 결과 이미지를 기기에 저장할 때 `job_id`도 같이 저장해 주세요.
- 메모는 서버에 저장하지 않아요. 사진처럼 기기에 저장해 주세요.

실패: `422 INVALID_REQUEST` (`X-Device-Id`가 없거나 형식이 맞지 않음)

## 6. 카드를 얻는 방식

- 작업이 `done`이 되는 순간 **서버가** 카드를 정해서 `result.card_ids`에 넣고, 그 기기의 컬렉션에 자동으로 기록해요. 앱이 따로 획득 등록을 호출할 필요는 없어요.
- 같은 카드를 여러 번 얻으면 `photos`에 사진이 쌓여요. 진행도는 늘지 않아요.
- 지금은 서버가 카드를 **무작위로** 골라요. AI가 미쿠의 포즈를 알려 주게 되면 그 포즈의 카드로 바뀌고, 응답 모양은 그대로예요.
